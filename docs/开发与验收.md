## 开发顺序

| 阶段 | 交付物 | 完成证据 |
| --- | --- | --- |
| 1 · 菜单栏与设置 | 可运行的 macOS 应用、一个状态项、图标资源位、原生设置和登录项 | 用两个模拟账号演示总数、账号菜单、默认账号切换。留存浅色／深色和选中状态截图 |

## 双账号验收

使用两个可单独识别的测试邮箱 A、B，使浏览器的登录顺序与应用添加顺序相反。以下初始数值按邮件封数准备，Gmail 网页若开启会话视图，应展开会话或用 INBOX 的 messagesUnread 核对。涉及故障的测试用本地伪造的 API 响应与临时存储驱动。各场景可独立复位。

| 编号 | 操作 | 可观察的通过条件 |
| --- | --- | --- |
| 01 | A 有 2 封未读，B 有 5 封，依次添加 | 数字从 2 变为 7。各账号有自己的最近成功时间。两次授权均无历史邮件通知 |
| 02 | 重复添加 A、取消一次添加、为 A 重新授权时选 B | 仍只有两行。B 的授权和计数保留。选错时提示目标 A |
| 03 | 默认 A，左键一次。设 B 为默认，再左键。从菜单打开 A | 三次分别进入 A、B、A。缺少浏览器目标登录时进入选择或登录流程。验证含加号或 Workspace 域名的地址编码 |
| 04 | 在同一轮检查前给 A 寄 3 封、给 B 寄 1 封 | 新增总计 4 封未读时显示 11。收到 A 的 3 封摘要和 B 的 1 封摘要。切换默认账号再点击 A 的通知，仍进入 A |
| 05 | 在手机读掉 1 封，再在网页把一封旧邮件标未读 | 两次检查分别减 1 和加 1。均不触发新邮件通知 |
| 06 | 新邮件在检查前被读过但留在 INBOX。另将旧邮件移回 INBOX | 前者产生 1 封新邮件通知。后者仅按未读状态更新计数。仅在归档、已发送、垃圾箱、垃圾邮件的新增消息均不通知 |
| 07 | 模拟同账号两页出现相同 ID。B 的数据中也使用该 ID | A 只计一次，B 独立计一次。再检查一次无新增通知 |
| 08 | 分别使第二页、候选标签查询、未读查询、文件保存失败，再重试 | 失败时原游标、计数和最近成功时间保持一致。完整成功后只产生一个对应账号批次 |
| 09 | 令 A 的 history.list 返回游标过期 404，再模拟 A 的同步文件丢失 | 两次都只为 A 重建基线。均不发送历史通知。B 在这期间仍能收到新邮件提醒 |
| 10 | 撤销 A 授权，给 B 寄一封，再重新授权 A | 菜单显示 A 待授权及旧数据时间。B 正常更新与通知。修复后的 A 从有效游标继续，游标失效则静默建基线 |
| 11 | 检查在途时移除默认账号，随后返回成功响应。重新添加同账号 | 默认目标和合计立即更新，已移除实例的凭据、状态、通知清除，迟到结果不起作用。重新添加只建基线。移除全部后仍可添加 |
| 12 | 模拟合计 0、99、100、105。逐一切换数字设置 | 默认分别显示纯图标、99、99+、99+。菜单可见真实值。取消隐藏零显示 0。关闭数字后全程纯图标。初次同步未知不会显示 0 |
| 13 | 一账号从未成功，另一账号有缓存，再断网、唤醒、恢复联网 | 能区分未知、旧值、真实零。自动模式恢复后合并触发，每账号最多一个在途检查。项目／账号级限流各自按方案退避 |
| 14 | 遍历四档自动间隔并改为手动，经历启动、唤醒、联网再点立即检查 | 自动模式依所选周期工作。手动模式在上述系统事件后无查询，用户检查生效 |
| 15 | 分别关闭声音、应用通知、系统通知权限，开启专注模式，随后恢复 | 关闭声音时静音。关闭通知时数字继续更新。尊重系统展示策略。重新开启无需补发关闭期间的邮件 |
| 16 | 启用「系统登录时提醒已有未读」，依次测试零未读、有未读、同轮有新邮件、普通手动启动 | 登录项自动模式分别无摘要、每账号一条未读摘要、仅新邮件通知。普通启动无登录摘要。默认关闭时无已有未读摘要 |
| 17 | 在原子提交前、已提交待发、已标记投递中三个位置中断进程 | 依次表现为从旧游标重试、恢复待发、核对系统记录并避免重复。记录最后一种情况下可能缺失的提醒 |
| 18 | 启用／停用系统登录项，重新登录 macOS，关闭偏好设置，再退出应用 | 启动行为与系统实际状态相符，无 Dock 图标或自动弹窗。关闭设置后仍检查，退出后进程及检查结束 |
| 19 | 用浅色、深色、菜单选中背景查看原图与分发所选图标 | 官方原图与官方资源一致、无重绘染色。模板图标随系统变色。小尺寸可辨，数字在图形外。记录每个位置的素材来源与适用用途 |

## 运行与发布记录

- **同步与隐私。** 用受控测试响应核对每个账号的请求与状态文件。无变化时每轮只有历史和 INBOX 计数两次 Gmail 请求。检查 HTTP 字段掩码、Keychain 条目、偏好文件和脱敏日志，只留必要信息。移除 A 后核对 A 的清理及 B 的持续运行。
- **真机与性能。** 记录 macOS 版本、芯片、构建号和账号数。在默认 60 秒间隔下分别记录单账号、双账号连续 10 分钟空闲 CPU、常驻内存与请求量，再观察批量来信后的回落。注明 50 MB 为优化目标。Apple Silicon 和 Intel 的实际运行结果与仅编译通过分别记录。
- **个人试用。** 使用自有 OAuth 客户端和测试用户，跨进程重启验证 refresh token，再完成双账号浏览器路由、真实通知和睡眠恢复。此阶段无需部署服务端。
- **公开分发。** 记录最终应用名称、各位置所用图标的用途依据、OAuth 受众与审核状态。用签名公证后的下载包在干净用户环境运行上述关键流程。文档评审、模拟测试、真机测试、分发包验证分别注明日期和结果。
